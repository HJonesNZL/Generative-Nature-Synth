# Native live-source milestone — 7 November 2026

The milestone retains two separate meanings: current bird acoustic activity at listening stations, and newly published shark location snapshots for provider subjects. An acoustic station is not an identified animal. A provider subject is not yet a reconciled animal/deployment identity. This milestone does not create continuous animal tracks, extrapolate motion, or relabel historical fixes as current observations.

## Portable implementation boundary

`native/include/atlas/collection.hpp` and `native/src/collection.cpp` implement a synchronous, worker-confined C++20 collector with an injected HTTP callback. There is no Python subprocess or required Python production runtime. The parent app owns worker lifetime, explicit collection controls, interprocess exclusion, scheduling, cancellation and the HTTP adapter. Network, JSON, SQLite, allocation and exceptions remain off the audio callback.

The collector accepts only `birdweather` and `nzsharks`. HTTP requests use the four public routes already in the Python prototype. Bootstrap values can supply only a percent-encoded public subject-group query value, never another host or path. Callback responses are capped at 4 MiB and parsed as bounded JSON. The parent adapter must enforce finite timeouts, cancellation and no redirects. Normal polling minimums are 60 and 900 seconds; provider Retry-After/backoff can make them longer.

The library path must be absolute with an existing parent. A new schema-v3 library is created with `metadata.native_collection_owner=animal_atlas_native_v1`. Reopening an existing file requires that marker and schema version in a read-only probe before writable opening. An unmanaged owner library or final symlink is rejected. The app uses its own managed `live.sqlite3`; it must never hand the existing recording database to this writer. Existing read-only native library/session readers accept the new schema, with initially empty session tables. Capture, snapshot creation and session writes are separate work.

A poll records its attempt, fetches outside the ingestion transaction, validates canonical events and commits revisions, current-event indexes, poll evidence and source state atomically. Deterministic event fingerprints deduplicate overlaps; changed source records create non-live corrections preserving first-seen time. The first valid snapshot per collector lifetime remains non-live, including after app restart. A successful capped snapshot or valid empty snapshot establishes arrival readiness independently of full coverage. On later polls, only a genuinely new event observed strictly after the previous attempt is live eligible; newly discovered older or delayed/backfilled records remain baseline and corrections never pulse. Failure attempts advance that cutoff, suppressing recovery backlog. UTC observation times are normalized independently of ingestion times. No synthetic arrivals enter the live database.

Invalid records and deferred future timestamps are counted. An invalid-only or future-only response does not establish arrival readiness. Such records do not complete an initial coverage baseline or advance the qualified completeness checkpoint. Pagination exhaustion, record validity and observation freshness remain separate facts; hitting the four-page limit is visible degradation. Malformed pagination or failed fetches commit no partial event batch. Previously stored records and successful timestamps survive failures. A gap between successful BirdWeather fetches longer than the ten-minute observation window sets a sticky warning, including for a perpetually capped source with no fully complete poll. Neither pagination exhaustion nor this warning establishes full completeness.

## Persisted health contract

`sources.status` retains these JSON keys, suitable for read-only UI queries:

- `enabled`, `configured_poll_seconds`, `last_attempt_at_utc`, `last_success_at_utc`, `last_complete_at_utc`;
- `last_error` (redacted code or null), `consecutive_errors`, `retry_delay_seconds`, `last_poll_complete`, `pagination_exhausted`, `baseline_complete`, `arrival_baseline_established`, `arrival_window_start_utc`;
- `last_poll_inserted`, `last_poll_corrected`, `last_poll_duplicates`, `invalid_records`, `deferred_future_records`, `pages_fetched`;
- `latest_observation_at_utc`, `unique_events`, `possible_unrecoverable_gap`, `completeness`, `freshness_claim`, `publication_lag_seconds`;
- `permissions_status`, `technical_status`, `monetary_cost`; BirdWeather also retains `region` and observation-window start/end.

`Collector::sourceStates()` exposes the typed subset needed by the app: source ID, latest attempt/success/observation, redacted error, record count, last-poll completeness, gap, retry delay and error count. These are worker-owned reads. Persisted `enabled` means the source was enabled for collection, not that a process is still running. UI connection state must combine current worker state and cached timestamps, and must show fetch age separately from observation age. The catalog API uses an independently persisted store ID and durable revision sequence. On a fresh map baseline, the host reserves at most half the requested event budget (up to 100 slots) for current positioned `individual_fix` revisions, fills the remainder with newest revisions, deduplicates by revision and returns sequence order. This source-neutral bounded coverage keeps older animal-position snapshots visible beside busy acoustic activity. Single-event requests retain the newest revision. Baselines never pulse and their cursor still advances to the pinned high water. `tests/map_source_coverage.py` verifies 1,200 newer acoustic revisions plus older shark/seal fixes, corrected current values, host restart, limits and subsequent live cursors.

## Verification and remaining qualification

The new `native/tests/collection_tests.cpp` uses disposable libraries and injected provider-shaped fixtures only. It verifies unmanaged-file and symlink rejection; current string certainty; UTC offsets; station/subject identity distinctions; baseline suppression; arrival eligibility; deduplication and corrections; restart; first-seen preservation; degraded/invalid/future records; sticky gaps and honest observation freshness; response/page/cursor bounds; GraphQL redaction; Retry-After; config-token nonpersistence; GeoJSON coordinate order; existing native read-only session compatibility; and transaction rollback after an injected storage failure. A permanently capped-source regression verifies that fresh post-attempt observations become live while partial-coverage warnings remain visible, and that backfills, corrections, recovery backlog and the first snapshot after restart do not pulse. A valid initially empty snapshot also establishes arrival readiness.

A direct C++20 build with `-Wall -Wextra -Wpedantic -Wconversion -Werror` passes. The same fixture suite passes AddressSanitizer and UndefinedBehaviorSanitizer. Bounded public probes verified provider access and exposed the legacy certainty bug. Subsequent parent tests exercised actual JUCE HTTP, the native Collect control and UI reload, and a second bird poll with genuine fresh arrivals. See the [final integration qualification](../../evidence/library-live/qualification.md) for exact receipts. Sustained polling remains unqualified. No ongoing owner collector was stopped/restarted and no fixture was written to an owner database.

A third source should be added only after an actual recent anonymous response and its animal/deployment/time/quality/rights metadata have been checked. The public ATN archive is a stronger evidenced next historical expansion than an unverified claim of a global live feed. Generic occurrence sources remain optional and cannot substitute for identified-animal tracking.
