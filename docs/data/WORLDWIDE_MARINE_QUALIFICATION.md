## Whale Safe

[Official API access page](https://whalesafe.com/get-involved/) describes daily Whale Presence Updates and directs API inquiries to its team. It publishes no endpoint/schema, fee commitment, authentication policy or observation-data licence there. No inquiry was sent. Public website availability does not establish redistribution permission.

[Official methodology](https://whalesafe.com/methodology/) distinguishes 15-minute analyst-reviewed acoustic intervals from daily presence summaries. The combined regional rating also incorporates sightings and predicted habitat, with a five-day lookback. Acoustic positions refer to the listening platform; exact whale positions and animal counts are unsupported. Visual sightings can arrive after boats return to dock. A daily rating cannot be converted into a timestamped whale fix, and a rating is not an individual track. The documented geography is California regions, not worldwide coverage. No actual current API record was obtained, so freshness is unqualified.

## iNaturalist multi-taxon connector qualification

This separate sightings connector is implemented; it does not fill the marine acoustic gap. [Official API practices](https://www.inaturalist.org/pages/api+recommended+practices) specify roughly one request/second and 10,000/day; [official schema](https://github.com/inaturalist/iNaturalistAPI/blob/main/lib/views/swagger_v1.yml.ejs) documents updated-at ordering. Queries use Animalia, public locations, CC0/CC-BY observation licences, and an actual observed-time window. Only those licences are admitted; media is excluded. Actual observation timestamp/offset and reported positional accuracy are preserved. Date-only/future/private/obscured/malformed records are excluded. Observation IDs never identify individual animals.

A bounded 200-result production request for 2026-11-06T04:00:00Z through 2026-11-07T04:00:00Z returned **7,331,002 bytes**, exceeding the 4 MiB application limit. The implementation now requests **30 results**, ordered by update time to admit late reports/corrections within the observed window. The exact revised public unauthenticated request returned **1,528,536 bytes; 30 admitted; zero excluded**. Saturation remains incomplete: this is a bounded worldwide sample, not complete worldwide coverage or an archive. Larger individual responses still fail explicitly at 4 MiB.

The 24-hour observed window excludes older newly discovered late uploads/updates. Provider `created_at` and `updated_at` are separately validated and retained as publication time and provider record revision; observation time is never replaced by either.

Managed live storage now revalidates up to 30 previously admitted observation IDs per poll, in persisted round-robin order, through `https://api.inaturalist.org/v1/observations?id=<comma-separated-numeric-IDs>&taxon_id=1&license=cc0,cc-by&geo=true&geoprivacy=open&taxon_geoprivacy=open&per_page=30&page=1`. One exact-ID public request was verified against observation 413281880. Only a complete, valid exact response with expected identities permits absence-based withdrawal. Missing/private/unlicensed/deleted observations are removed from managed current events and all corresponding managed revisions/raw records; store identity rotates atomically to force the UI to clear and rebuild its baseline. Valid returned corrections update existing records even outside the fresh discovery window. Timeouts, oversized/truncated/malformed responses and unexpected IDs never imply withdrawal and do not advance the revalidation cursor. Revalidation failure remains visible in source status. The network adapter must space the two possible requests by at least one second; the poll interval remains 15 minutes.

This is bounded best effort: recheck latency grows with retained record count, and source failures can delay revalidation. The explicit event flag reflects that limitation. SQL rows are removed, without promising forensic erasure of filesystem/WAL copies or external backups. Separately frozen session events, saved pieces and exported/offline archives are historical snapshots and are not silently rewritten or invalidated by live-store withdrawal; their original attribution/permission-at-fetch and independent reuse obligations remain visible. No historical republication clearance is implied.

Correction/deduplication, complete-absence withdrawal, failed/truncated/malformed recheck retention and store-identity reset tests use disposable native libraries. Schema/privacy tests and ASan/UBSan pass. No owner state, collector process, audio device or DAW was used.

Final privacy check: both request forms now include `taxon_geoprivacy=open`, documented in the official schema as conservation-status-derived geoprivacy. A bounded exact-ID request with both privacy filters still returned public observation 413281880 (null geoprivacy/taxon-geoprivacy), confirming null/open records are not excluded. Explicit revocations returned despite filters retain only numeric ID and recognized permission metadata; complete exact-ID responses can withdraw those IDs without retaining coordinates or timestamp evidence. Mixed malformed records, wrong IDs, inconsistent counts, or additional pages fail closed without withdrawal. Tests preserve a second admitted ID when the first is explicitly revoked.
