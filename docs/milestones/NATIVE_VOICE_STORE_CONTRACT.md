# Native voice draft and preset sidecar contract

This engineering slice exposes one implemented `struck` synthesis type. It supplies a global definition (`default`, target group `native`) and independent species definitions (`species:` plus the unchanged source species ID). There is no inheritance, individual voice, mapping editor, additional synthesis type, or automatic save. UI adapters report `inheritsFromId: null` and no inherited override IDs. The global master level remains a separate engine setting (the host default is −18 dB).

## Ownership and API

`atlas::VoiceStore` is confined to one host/UI worker. It owns mutable drafts, parameter gesture state and one SQLite connection. Its constructor takes a dedicated sidecar path and optional species catalogue; `registerSpecies` atomically adds/renames species and leaves existing drafts intact. Saved species absent from a later catalogue remain exposed, using their source ID as the label until the backend supplies a display name. Display names are backend metadata and are not saved as preset content. Default plus species definitions are bounded to 513 total across the live store; durable species rows are bounded to 512, plus the optional saved fallback row, so reopening can never exceed 513 definitions. Exceeding either bound is an observable `full` error.

`getVoice` and `voices` return copied snapshots. Parameter values occupy the `voiceParameterIds` order: tuning, attack, decay, gain. `previewParameter` validates and computes the exact prospective snapshot without mutating draft/gesture/revision state. The host uses this to validate and submit settings to the engine before calling `setParameter` on the same worker. The host must not interleave another mutation between preview and apply. Audio callback code never calls the store; the engine owns its bounded numeric voice bank and publication path.

A parameter gesture strictly follows `begin`, zero or more `change`, then `end`. Begin records the gesture without changing the parameter; change/end apply the value, and end closes it. Every accepted phase obtains a monotonically increasing host-local integer change revision. Different parameters can have independent active gestures. If an end phase times out in the audio adapter, the adapter disables output, restores the last acknowledged settings and closes that gesture at the last acknowledged value, while reporting the failed edit. This keeps Save, Revert and subsequent gestures usable. Save and Revert reject every open gesture. The UI flushes/awaits gesture completion before invoking either operation and closes abandoned gestures on selection changes. Editing is allowed on a read-only store; explicit Save reports read-only and preserves its draft.

## Parameter encoding, units and semantics

| Parameter | Normalized encoding | Engine value | Default |
| --- | --- | --- | --- |
| `tuning` (Transpose) | linear, rounded to nearest integer semitone | −12 through +12 semitones | 0 |
| `attack` | logarithmic | 0.002 through 0.100 seconds | 0.008 s |
| `decay` | logarithmic | 0.100 through 3.000 seconds, T60 | 0.650 s |
| `gain` | linear | −60 through 0 dB | 0 dB |

The normalized boundary accepts only finite doubles in [0,1]. Unknown voice/parameter IDs and invalid gesture enum/order values fail observably. Stored tuning must already be quantized, within 1e−10 of its integer step. Stored values are validated independently of SQLite affinity, including column storage types, finiteness, bounds, integer revision, and per-row schema version. Real settings affect future notes; the engine snapshots settings on note admission. Species hash pitch remains the base pitch and Transpose shifts it. Conversion returns exact declared defaults and endpoints before evaluating logarithmic curves, so untouched presets preserve legacy engine default values across math-library implementations.

## Durable state and failure policy

Only explicit `save(id, expectedSavedRevision)` writes preset values. New/unsaved definitions have saved revision 0; saving writes revision 1, then increments on every successful save. Revisions use integers bounded by SQLite's signed 64-bit range; the JSON adapter must encode them as decimal strings. Host-local change revisions are separate from saved revisions. `dirty` compares the current normalized values with the host's last loaded/saved values.

Save uses `BEGIN IMMEDIATE`, validates the current durable row, checks the caller's expected revision against both the draft's base and the durable row, writes one complete row, and commits before acknowledging or marking the draft clean. A concurrent writer yields `conflict`; draft content and its base revision remain intact. Busy/read-only/full/storage/commit failures roll back and leave the draft unchanged. Revert reads the latest durable row, replaces the draft and clears dirty state. A durable row known to exist that subsequently disappears is corruption, not a silent default restore. Corrupt values and unsupported formats never become default presets.

The sidecar uses SQLite rollback journaling with `synchronous=FULL`, one `voice_presets` table, application ID `0x41545653` (`ATVS`), database `user_version=1`, and per-row `schema_version=1`. Rows contain the opaque definition ID, integer saved revision and four normalized real values. All IDs are bound SQL parameters, never filenames or interpolated SQL. Species IDs are nonempty, at most 256 bytes, without ASCII controls; names are at most 512 bytes. There is no JSON blob or file per voice. Nonempty unrecognized databases, other applications, unknown schema versions, unexpected schema objects/columns, duplicate/invalid IDs and malformed row types are refused. No production migration is performed.

The caller must choose an application-owned preset sidecar path separate from the animal library and must create any desired parent directory. The store refuses an existing animal library by application/schema identity without changing its schema or data. It does not inspect or write an owner database as part of tests. SQLite access, allocation and exception handling stay off the audio thread. Errors carry `VoiceStoreErrorCode` (`invalidArgument`, `notFound`, `gestureActive`, `conflict`, `readOnly`, `full`, `corrupt`, `unsupportedSchema`, `busy`, `storage`); adapters must preserve an observable failure.

## Verification

`native/tests/voice_store_tests.cpp` uses only an automatically deleted temporary directory. It checks defaults/ranges, preview isolation, strict gestures, tuning quantization, species independence, explicit save/reopen, absence of autosave, durable catalogue recovery, two-connection CAS/revert, read-only failure, SQLite busy rollback/retry, uncommitted transaction rollback, capacity and atomic registration, exact sidecar metadata/content, generated-column schema rejection, >2^53 exact revision handling/exhaustion, concurrent-host species capacity, refusal to modify a disposable owner-like database, and corrupt/unknown stored values/schema. Standalone compilation uses C++20 and project warning flags as errors; the parent integration adds the test to CMake/CTest. `tests/native_voice_checks.py` and `native/tests/studio_host.cpp` also verify the real host protocol with a synthetic clocked output, including no driver restart or transport change during edits, no animal-library writes, competing-host save conflicts, failed preparation slot recovery verified against captured synthetic PCM and a test-only callback stall that forces end-gesture timeout recovery. Concurrent sidecar initialization is serialized and rechecks metadata after acquiring its transaction lock. A rollback test is not a physical power-loss qualification. No real owner file, audio device, DAW session, or actual listening test is used by these storage checks.
