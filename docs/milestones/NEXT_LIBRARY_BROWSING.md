# Live collection and scalable historical libraries — implementation record

## Objective and diagnosis

The owner expanded the next browsing milestone to include a range of live wildlife streams. The running Project Recovery app had no wildlife library attached and no collector process was running when inspected on 7 November 2026. Its read-only change-feed display existed, but it did not run a collector; the old BirdWeather normalization also rejected the provider's string certainty field. Continuous identified-animal tracks were not connected. Existing owner databases, settings, processes and older release bundles are preserved.

Deliver the two verified public streams inside the native app: NZ bird acoustic activity and NZ shark latest-position snapshots. Keep their identities, times and coverage separate. Extend historical browsing beyond the first 100 saved pieces, remove measured repeat preparation work and preserve integrity under concurrent library changes. No new paid service, key, hosting or production Python dependency.

## Completed workstreams and contracts

1. **Portable collection.** C++20 `Collector` owns a separately marked schema-v3 managed library. Synchronous fetch callbacks run on a dedicated collection worker; normalized records, immutable revisions, raw evidence and source status commit atomically. Existing unmarked libraries are refused for writing. Four exact public HTTPS routes, bounded JSON, source-specific station/subject semantics and no synthesized movement. Fresh arrivals, baseline, corrections and backfills are distinct. A partial first snapshot establishes arrival readiness independently from full coverage; subsequent fresh records can ping even when a busy window exceeds four pages. Restarts suppress backlog.
2. **Native service.** JUCE provides serial HTTP with an eight-second whole-request cancellation deadline, no redirects and a 4 MiB response bound. Bird/shark minimum intervals are 60/900 seconds. Retry-After and error backoff survive restart; explicit pause cancels buffered work without inventing a source failure. Scheduling/status control avoids DB/network work under its UI-facing mutex. No audio callback work is added.
3. **Standalone integration.** Collection starts disabled every launch. Collect explicitly selects sources, switches to `live.sqlite3`, retires the prior document epoch and refreshes capabilities/UI. Switching back to an external library pauses native collection. Existing archives remain read-only. Source controls and health are available only when the service starts successfully. No terminal collector is started or stopped.
4. **Live interface and map.** Existing Collect disclosure holds selection/start/pause; source rows separate fetch age from observation age and distinguish partial coverage, gaps and actual failures. The initial bounded map snapshot reserves up to half its slots (maximum 100) for current positioned fixes, then fills with recent activity. This prevents high-volume acoustic detections from erasing quieter positions. It does not make old fixes current or establish individual identity. Large globe and draggable NZ detail remain intact.
5. **Saved-piece browsing.** `listSessionsPage` uses creation-time/id keyset cursors, limit 1–100, a per-reader identity and SQLite data-version fence. No total COUNT or whole-library UI list. React retains one 50-row payload and at most 128 previous cursor tokens; forward traversal has no artificial final-page cutoff. Selection survives screen switches and pages. Stale cursors require explicit refresh; missing/unreadable/incompatible library errors are distinguished.
6. **Material preparation.** One verified material timeline is reused for preparation and pages while library identity/revision match. A revision change invalidates it; integrity checks run again before use. Event-page responses include a revision fence; stale pages clear accumulated display records. Existing prepared playback remains separate from this one-piece cache. No unlimited cache or alternate synthesis engine.
7. **Qualification and release.** Native fixture, protocol, service and UI boundary tests; large-library before/after benchmark; sanitizer checks; desktop layout and real WKWebView checks; explicit two-provider network smoke; saved-scene/render/backup/recovery regression; signed local bundle and outside-repository ZIP launch. See the [qualification record](../../evidence/library-live/qualification.md) for actual results and limitations.

GPT-6.1 SOL agents implemented disjoint collection, storage/service and UI/test streams; parent integration added native controls, epoch fencing, package checks and release documentation. Source research is recorded in [LIVE_SOURCE_MILESTONE](../data/LIVE_SOURCE_MILESTONE.md).

## Measured workload

`LargeLibrary-20000-events-3003-pieces-v1` contains 20,000 synthetic mixed receiver/fix events and 3,003 sealed pieces (61,214,720-byte database). Three fresh-host runs per binary measured median catalog→prepare at 1362.35 → 729.53 ms, warm prepare at 644.51 → 8.26 ms, and warm 500-event pages at 23.55 → 23.12 ms. Process peak RSS was 118.44 → 114.48 MB. The optimization removes repeat integrity/JSON loading during preparation; it does not materially speed up page serialization. OS caches were not flushed, and these are neither physical playback measurements nor guarantees for arbitrary archives. Final integration reruns correctness separately from this recorded comparison.

## Explicit limits and next work

- BirdWeather is listening-station activity, not the location of an identified bird. Shark source subjects lack reconciled animal/deployment IDs and expose snapshots, not continuous tracks. Actual observation age must remain visible.
- Public Movebank and ATN probes qualified historical records, not a third current live feed. The documented ATN archive has genuine identities, quality metadata and acknowledgement-based reuse terms; it is a candidate for the next historical import connector. Verify each dataset's actual times and terms before enabling it. Source access and redistribution rights are separate.
- Native collected data persists, but freezing/importing new historical pieces remains outside this milestone. Existing large libraries and sealed soundscapes are fully browsable/preparable. Live data-to-audio sonification is also separate from this tracking milestone.
- Display retains up to 2,000 events and 500 markers; saved recipes retain the existing 50,000-event admission bound. Managed collection stops with an explicit storage error at its 512 MiB cap or low disk space; it never silently prunes data.
- The [worldwide wildlife source milestone](GLOBAL_WILDLIFE_SOURCES.md) adds regional bird collection, qualification of a current non-bird source and separate acquisition of identified-animal records. The following library work supports saving and replaying that material.
- Native capture/freeze and bounded historical import into the managed library, including provenance, source-specific coverage and resumable import progress. Qualify an identified-animal historical source before offering it. Keep musical preparation reproducible and expose unknown coverage; then integrate live sonification as its own tested audio workflow.
- Human listening, device hotplug/sleep/wake, long-running provider soak, multi-machine qualification, public signing/notarisation and VST3 hosting remain release gates. No live-input DSP budget is imposed.
