# Soundscape offline export contract

A native UI worker starts an independent bounded offline job against a selected self-contained `.atlas-scene`. The worker verifies the complete scene and expected scene hash, then renders the exact captured numeric globals, complete composition and ordered regional settings and independent species/fallback profiles through the existing AudioPlan/AudioRenderer. It neither opens a source animal library nor reads mutable preset drafts or live playback state. Export retains the captured sample rate (the native UI currently captures 48 kHz), stereo 24-bit PCM, exact time basis/rational speed and the same editable-voice maximum-tail policy used for live scene playback, plus the declared regional 12-second horizon and final 20 ms fade whenever the prepared scene has an active wet path.

## Control and worker ownership

`RenderJobs(outputDirectory, engineSourceSha256)` owns one offline `std::jthread`, one active job, at most sixteen retained terminal snapshots, a control mutex and small atomic frame counters. The caller chooses an existing application-owned output directory; symlink directory inputs are refused. The engine source hash is the actual compiled source identity passed by the host and must be lowercase SHA-256 hex. No new paid dependency, provider request, audio device, output-driver lifecycle or callback work is introduced.

`start(scenePath, expectedSceneHash, jobId)` validates bounded opaque IDs and expected SHA-256, rejects an active job or retained duplicate ID, and starts the thread. Loading, scene verification, AudioPlan compilation and rendering happen inside that thread. The UI API never waits for those operations. A previous completed thread is joined after it has retired its large plan/scene/file resources and published terminal status as its final operation. The service supports one active render, no queue. Callers generate opaque IDs containing only `[A-Za-z0-9_-]`, one through 64 bytes; the host currently generates 32 lowercase hex digits. Output is always `<jobId>.wav` within the configured directory. Clients cannot submit an arbitrary output path.

`get(jobId)` copies a snapshot under the control mutex. Snapshots expose ID, `running/completed/cancelled/failed` state, atomic frames written/total, captured sample rate once prepared, completed output filename, redacted observable error and whether cancellation was requested. Loading/compilation can report zero totals. Progress is the count of frames actually written, not a fabricated percentage; an acquire/release publication keeps written frames bounded by the visible total. Output filenames are cleared on cancelled/failed terminal states. The oldest terminal metadata expires after sixteen retained results; eviction never deletes a rendered artifact. Missing/expired jobs fail explicitly. Snapshot/control mutexes are unrelated to the live audio callback.

`cancel(jobId)` requests the active job's stop source and returns current status. It does not prematurely label a job cancelled. Destruction requests stop and joins the thread while its state remains alive. Worker-local scene, plan, renderer and staging resources are retired before terminal publication, so observing a terminal snapshot also observes completed staging cleanup. Thread lifetime and snapshots cannot depend on the UI retaining a temporary result.

## WAV cancellation, publication and format

The existing `renderWave(plan, output, recipe, blockFrames=512)` API retains its behavior through an optional final `RenderControl`. That control contains a `std::stop_token` and optional atomic pointers for frames written/total. The adapter checks stop before starting, before every bounded render block and immediately before atomic publication; cancellation throws typed `RenderCancelled`. Rendering uses the same engine and fixed scratch arrays as the existing renderer. It does not reimplement DSP or accept new defaults at export time.

WAV remains little-endian stereo 24-bit WAVE_FORMAT_EXTENSIBLE, PCM subtype, front-left/front-right mask, fact sample count and LIST/INFO/ICMT recipe metadata. PCM quantization and silence behavior are unchanged. The export job uses 512-frame blocks; output is invariant under other accepted block partitions. The captured sample rate is preserved rather than silently changed. The plan is built with `editableVoices=true`, matching live playback's maximum permitted voice tail and total frames, while every note still snapshots the actual captured species setting and its derived regional route. Enabled spatial processing preserves stereo through quantization. Mono downmix is not substituted at export.

A new exclusive sibling `<output>.rendering` directory holds the temporary WAV. Existing files, symlinks and foreign staging directories are refused; the service never replaces or adopts them. Ordinary failure/cancellation destroys only this job's owned staging directory. A completed flushed/closed WAV is published with the existing exclusive same-filesystem hard link. Unsupported hard links and publication conflicts fail. Shutdown and cancellation do not delete existing files or completed artifacts.

Cancellation is cooperative through the last prepublication checkpoint. A request arriving after that checkpoint may lose to publication; successful publication is always reported completed, never cancelled. A cancelled terminal state always has no published job artifact. A completed terminal state retains the complete artifact even if a concurrent late cancellation request was recorded. The final snapshot resolves this race. Cancellation requested while loading/verifying/compiling is checked between those bounded worker stages; the implementation does not interrupt SQLite or destroy worker state concurrently.

## Compact traceability recipe

`soundscapeRenderRecipe(scene, engineSourceSha256)` is the shared worker-side recipe builder used by asynchronous `RenderJobs` and CLI `scene-render`. It rejects malformed source SHA-256 values. Both consumers embed identical complete recipe JSON for the same scene/build; their PCM planning and rendering remain unchanged.

The embedded JSON is deliberately small and references the authoritative self-contained scene rather than copying up to 513 profiles into a 16 KiB WAV comment. For schema 1/2 it retains recipe revision 2 and its existing field set. Schema 3 uses recipe revision 3 and additionally records `regional_tail_policy=active_wet_12s_final_20ms_fade`. Each recipe records engine identity, full scene SHA-256, the selected scene’s actual schema revision (including preserved legacy schema 1), synthesis/mapping revisions, time basis, exact numerator/denominator speed, sample rate, compiled engine source SHA-256, two channels, 24 PCM bits and `editable_voice_maximum` tail policy. The selected scene itself carries every frozen event/provenance field, original bounds and exact numeric voice/global/composition value. Schema 3 uses synthesis 4 / mapping 3 and stores all ordered region settings; schema 2 retains synthesis 3 / mapping 2 and retains the complete composition tuple in its authoritative scene; schema 1 continues synthesis 2 / mapping 1 with composition disabled. Schemas 1/2 retain default disabled spatial settings and their original hashes. The recipe reports the captured schema rather than substituting the current writer revision. Neither a WAV preset name nor a later mutable preset lookup can alter that recipe.

## Failure and evidence

Control errors are typed `RenderJobErrorCode`: invalid argument, busy, missing/expired job or storage. Offline loading, hash, engine, file and publication failures produce a failed terminal snapshot with an observable redacted error. Corrupt scenes do not become silent/default sound. Job errors do not stop or reconfigure live playback.

`native/tests/render_job_tests.cpp` uses disposable scene/output/preset state only. It checks asynchronous start, a competing-job busy response, ID/hash validation, actual partial-render cancellation and staging cleanup, destructor stop/join, pre-start cancellation, terminal-history capacity/expiry, repeated jobs, corrupted/changed source scenes, no-overwrite and foreign-staging protection, late cancellation, and consistent cancellation/publication final states. It parses the WAV format/recipe and compares every 24-bit PCM byte against the live AudioRenderer using enabled composition with nondefault scale/tonic/tempo/density/variation/seed and the frozen six-character profiles and another block partition, including the exact maximum-tail total. The schema-3 fixture uses reported synthetic coordinates, two overlapping/dateline regions, stereo panning and echo/room sends; it checks stereo channel differences, added effect-horizon frames and nonzero 24-bit wet energy after dry voices end. It separately exports legacy schema-1 and schema-2 material with unchanged PCM and its actual schema/synthesis/mapping revisions. It exercises a 44.1 kHz scene to prove captured-rate preservation and an unrelated saved preset change during export to prove independence. Existing WAV format/oracle tests remain required after integration.

These checks are synthetic offline storage/export evidence. They do not establish owner listening acceptance, real-device or DAW performance, physical power-loss survival or a final synthesis palette. ASan/UBSan and integrated CTest results are reported separately after the agreed new DSP validation is available.
