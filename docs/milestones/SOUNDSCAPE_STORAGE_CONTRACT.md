# Self-contained soundscape storage, revision 3

The storage boundary copies an already verified frozen source timeline and the complete audible numeric recipe into one standalone `.atlas-scene` SQLite file. Recall reconstructs its Timeline and AudioPlan from those copies without opening the original animal library, source session, voice preset sidecar or any provider. A soundscape preserves genuine event JSON and its provenance; it does not fabricate observations. The synthesis revision identifies the implemented candidate engine, not an approved final instrument palette.

## Ownership, API and limits

`SoundscapeCapture` owns the soundscape name, descriptive `sourceLibraryLabel`, verified `SavedSession`, selected `TimeBasis`, exact rational `Speed`, original unscaled selected bounds, actual global `AudioSettings`, complete independent `VoiceProfile` values, schema revision 3, synthesis revision 4 and mapping revision 3. Schema-2 scenes retain synthesis 3 / mapping 2 and the original complete composition tuple. Recalled schema-1 material retains schema 1 / synthesis 2 / mapping 1 and disabled composition; saving it preserves that identity and original content hash. The library label is provenance text and is never dereferenced. The original session fields retain both observed/arrival bounds, requested-window policy, immutable state/origin, event count/truncation, source content hash and metadata verification quality. Legacy source metadata remains explicitly legacy/unverified; copying never upgrades its provenance claim.

`captureSoundscape(timeline, capture)` requires the `SavedSession` returned through `ReadOnlyLibrary::load`'s verified-session output. It validates each copied frozen event with the existing strict event-v1 validator and compares its decoded identities, positions and timestamps against the input Event. It reconstructs the Timeline using the supplied basis/speed/bounds and checks every scheduled event plus duration against the input. The selected bounds must equal the source session's original bounds for that basis. Nonselected original bounds are also checked. Capture retains the complete normalized JSON, including source attribution, permission/uncertainty/quality and genuine individual/deployment/station distinctions supported by event schema v1.

The original library checksum covers original source ordinal order; Timeline may sort differently by observed or arrival time. That checksum is retained as verified-source provenance, not falsely recomputed from a reordered timeline. The scene has its own independent canonical content SHA-256. Callers must not construct a purported verified session by hand in production; tests construct only disposable source libraries and load through the real reader.

A Soundscape owns one immutable Timeline and capture metadata with const accessors. It has no event-vector copy inside its metadata. It can be moved/copied only off the audio thread. `saveSoundscape(path, scene)` publishes a new file; `loadSoundscape(path)` verifies and returns independent state; `inspectSoundscape(path)` checks the exact schema and sealed bounded scalar header without event/profile material, and `listSoundscapes(directory, limit)` returns those summaries with visible per-file failures. The render control path can inspect the selected immutable hash quickly before delegating full load to its own worker. All methods perform allocation, filesystem and SQLite work on one serial worker, never a callback. Separate operations own separate connections. Plan publication, output transport, existing voice drafts and export-worker ownership belong to host integration.

Limits are 50,000 events, 16,384 bytes per normalized event, 64 MiB total event JSON, 513 profiles including fallback, a 30-minute scaled timeline ceiling and the current engine’s total render bound including active effect tails, and a physical file ceiling of 68 MiB. Listing returns at most 100 alphabetically ordered file paths after inspecting at most 1,000 directory entries; exceeding the scan cap is an observable capacity error. It reads only the small header and exact schema, not event rows or full profiles. It includes corrupt/unsupported files with an error and never silently omits their existence. `contentVerified=false` distinguishes a sealed-header listing from a full verified load. A valid header does not promise that unread event/profile material remains valid; full load is mandatory before recall/render.

## Complete numeric recipe

Globals contain sample rate, root MIDI, attack seconds, decay seconds and master dB. Schemas 2 and 3 additionally capture every `CompositionSettings` value: enabled, scale, tonic pitch class, tempo BPM, density, variation, seed and quantize. This is a copied numeric recipe; no mutable composition preset is consulted. Variation uses the same exact `max_digits10` double encoding as the other globals. Scale values are major pentatonic, minor pentatonic, major and natural minor (integers 0–3); density is sparse, balanced or active (0–2). Tonic is 0–11, tempo 40–180 BPM, variation finite 0–1, seed the full unsigned 32-bit range, and enabled/quantize are canonical 0 or 1. Disabled composition still retains and validates every setting. Each profile contains the unchanged species ID, integer transpose semitones, attack seconds, decay seconds, gain dB, integer `VoiceCharacter` (`struck`, `whistle`, `reed`, `bell`, `air`, `pulse`), brightness, roughness, pulse Hz and sweep semitones. These are actual numeric values, never references to a mutable preset name or lookup result. Slot zero is the explicit fallback (empty species ID). Every event species must have an explicit independent profile; additional captured profiles are allowed within capacity. Duplicate species, missing fallback or missing species profile fails. Preset changes after capture cannot change recall.

Schema 3 additionally captures complete `SpatialSettings`: enabled, amount, and at most eight ordered regions. Each region copies id, UTF-8 display name, south/north/west/east bounds, pan, gain dB, send, echo mix, delay milliseconds, feedback, nominal room seconds, tone and position-pan flag. Region identity/order and every exact numeric setting enter the scene hash. Reordering overlapping regions can change first-match routing and therefore changes both identity and rendering. Derived routes, delay storage and coefficients are reconstructed off-thread from this recipe.

IDs contain 1–64 ASCII letters/digits/underscore/hyphen and are unique. Names contain 1–128 valid UTF-8 bytes without C0/C1 controls. All numbers are finite. South/north are within ±90 with south<north; west/east within ±180, unequal and excluding the zero-width [180,-180] pair. [-180,180] covers all longitudes and other west>east pairs cross the dateline. Pan is [-1,1], gain [-60,0] dB, send/echo/tone/amount [0,1], delay [20,500] ms, feedback [0,.5], room [.2,2.5] seconds. Validation applies even when spatial processing is disabled. Schema 1/2 reconstruct exact default disabled spatial settings (amount .25, no regions). Attempts to capture nondefault spatial settings under either old schema fail rather than silently omit them.

The existing `AudioPlan` remains the validation authority for numeric settings, profile bounds, action compilation, voice and render limits. Storage invokes it off-thread and does not implement a second mapping or DSP engine. Unknown synthesis/mapping revisions fail; they never resolve to the current engine or current defaults. Extending the stored tuple requires an explicitly supported format/schema change, not an ignored field.

## File schema and integrity

Application ID is `0x41545343` (`ATSC`), `user_version=3` for new captures. Readers also support `user_version=1` and `user_version=2` with their original closed metadata and original hashes; all other versions fail. The table shapes are identical across all three versions. Schema 2 adds only eight mandatory closed scalar metadata keys: `composition_enabled`, `composition_scale`, `composition_tonic_pitch_class`, `composition_tempo_bpm`, `composition_density`, `composition_variation`, `composition_seed` and `composition_quantize`. It requires synthesis 3 / mapping 2. Schema 1 requires synthesis 2 / mapping 1 and reconstructs the original disabled composition defaults. Its original content is fully verified before replay, and is never silently rehashed or migrated. A schema-1 capture cannot represent composition settings other than those disabled defaults. Exactly three `WITHOUT ROWID` tables are allowed, with the exact DDL emitted by this version; unexpected tables, views, triggers, indices, generated/extra columns or altered schemas fail before rows are interpreted:

Schema 3 requires synthesis 4 / mapping 3. Its only format extension is mandatory scalar metadata `spatial_enabled`, `spatial_amount`, `region_count`, plus exactly 15 keys for each contiguous zero-based ordinal `region_<n>_`: `id`, `name`, `south`, `north`, `west`, `east`, `pan`, `gain_db`, `send`, `echo_mix`, `delay_ms`, `feedback`, `room_seconds`, `tone`, `position_pan`. The complete configuration is covered by both header and content hashes. Unknown ordinals/fields, missing fields, malformed flags, noncanonical doubles, invalid UTF-8, duplicate IDs and impossible configurations fail even if a caller recomputes the header seal. Metadata has an explicit 192-row read bound (the complete eight-region header fits); each key/value must have SQLite TEXT storage type. No extra region table or unsealed sidecar is used.

- `scene_meta(key TEXT PRIMARY KEY NOT NULL, value TEXT NOT NULL)` contains a closed mandatory set of scalar metadata keys. Text is bounded. Integer values use canonical decimal text; doubles use finite general-format decimal text with `max_digits10` precision and exact roundtrip validation. Zero has one canonical encoding. Bounds contain a presence marker and original signed microsecond endpoints; absent bounds have zero endpoints. Unknown/missing/duplicate metadata, malformed scalar types/encodings, unsupported engine/mapping and impossible bounds/counts fail.
- `scene_events(ordinal INTEGER PRIMARY KEY NOT NULL, original_seq INTEGER NOT NULL, event_json TEXT NOT NULL)` contains contiguous scene ordinals in prepared timeline order, original revision sequences, and the exact copied source-normalized event JSON. Events are parsed using the existing event-v1 boundary; unknown JSON fields, duplicate keys, invalid Unicode/types/identity, unsupported event schemas and malformed timestamps fail.
- `scene_profiles(slot INTEGER PRIMARY KEY NOT NULL, species_id TEXT NOT NULL, tuning INTEGER NOT NULL, attack REAL NOT NULL, decay REAL NOT NULL, gain REAL NOT NULL, character INTEGER NOT NULL, brightness REAL NOT NULL, roughness REAL NOT NULL, pulse_hz REAL NOT NULL, sweep_semitones REAL NOT NULL)` contains contiguous slots starting with fallback. Column storage types, integer ranges and numeric finiteness are checked independently of SQLite affinity.

The content manifest is SHA-256 over length-prefixed UTF-8 values: decimal byte length, `:`, then exact bytes. First comes `atlas-scene-v1`, `atlas-scene-v2` or `atlas-scene-v3` for the actual schema revision; then sorted metadata key/value pairs excluding `content_hash` and `header_hash`; then `profiles`, followed by every slot's species ID and canonical numeric settings in declared order; then `events`, followed by every prepared event's original sequence and exact JSON. The header SHA uses the same prefix and sorted metadata key/value framing, including `content_hash` but excluding `header_hash`. Both hashes are stored as lowercase 64-digit hex. This is corruption detection and consistency, not authentication against a party able to rewrite the bundle and its hashes.

Full load checks the header seal, strict schema, all events and profiles, reconstructed duration, numeric plan validity, and complete content manifest. Valid-looking edits to a global, profile, event or source metadata fail integrity verification. No unrecognized data becomes a silent preset default. Read transactions keep every check and row read in one SQLite snapshot. Files must be regular `.atlas-scene` files, not symlinks, and must have no `-wal`, `-shm` or `-journal` sidecars. The published bundle is a complete single file.

## Atomic save and failures

The caller chooses a new application-owned output path and creates its parent directory. The host should expose opaque scene IDs mapped to that owned directory instead of accepting arbitrary paths from UI clients. Existing files, directories and symlinks are never replaced, including a destination that appears during publication.

Save creates an exclusive sibling `<output>.saving` directory, writes a new SQLite file with rollback journaling and `synchronous=FULL`, commits, closes all statements/connections, then reopens the complete file through the strict full loader. Only verified completion is published using an exclusive same-filesystem hard link. Unsupported hard-link filesystems fail explicitly. Ordinary failures remove only this operation's exclusively owned staging directory. A process interruption may leave staging state; an existing staging directory is refused and is not deleted or adopted. Atomic publication does not claim parent-directory fsync or physical power-loss qualification.

Errors carry `SoundscapeErrorCode`: invalid argument, missing file, already exists, unsupported schema, corrupt, capacity or storage. Host adapters must retain an observable failure. No save writes the original animal library or voice store, no recall fetches source material, and no test uses the owner's state or active collectors.

## Verification

`native/tests/soundscape_tests.cpp` creates a disposable schema-v2 source library and loads through `ReadOnlyLibrary`, with original ordinal order intentionally different from observed timeline order. It unconditionally pins the pre-change canonical schema-1 manifest SHA-256, checks complete legacy load and save without schema/hash migration, and rejects corrupted legacy profiles. It saves complete globals, nondefault composition settings (including an adjacent representable double and maximum uint32 seed) and independent profiles, deletes the source library, recalls the bundle and compares full rendered floating-point PCM against the precapture result. It checks original provenance quality/hash, truncation, bounds, revision ordering and all current voice fields and exact composition settings. Composition tests reject unknown/missing composition keys, malformed enums/flags/ranges/noncanonical doubles and valid but integrity-breaking composition edits. Schema-2 manifest SHA-256 is pinned to the pre-spatial value `55377fdffad0fc41a1c3e8fa0048b73d75324488c59b5f709b3c617330606e02`; load/save preserve its schema/hash/default disabled spatial state and PCM. Schema-3 tests cover complete two/eight-region headers, adjacent representable doubles, ordered overlap precedence, UTF-8 names, stereo PCM and resealed malformed/unknown/missing/type-corrupted region fields. Offline export tests additionally compare composed wet stereo frozen-scene PCM against the renderer, including nonzero effect-tail output. It exercises no-overwrite, occupied staging, symlinks, truncated/non-SQLite files, orphan sidecars, unknown schema/metadata/events/versions, missing/duplicate slots, altered valid settings/material, wrong numeric storage types, re-sealed unknown/noncanonical metadata, event/byte/count/duration/speed bounds and bounded metadata listing with visible invalid entries. All fixtures are temporary and automatically removed.

An additional explicit artifact comparison is enabled only by `ATLAS_VERIFY_LEGACY_PCM_BASELINE=1`. It checks raw floating-point PCM SHA-256 `0f68e996870aa97401273e03f1bf7f7ef1f746a2d5fee340cefc59520197762e`, recorded from the pre-change engine on arm64 macOS with Apple clang 17.0.0 (`clang-1700.6.4.2`). The same flag checks pre-spatial composition PCM SHA-256 `6e39c8aaf34d2617dd97154387f46d4fdcbf377798665c984b265dd886aea98c` from the same platform. These optional checks detect exact regressions against that local baseline; byte order and cross-toolchain/libm bit equivalence are not a portable PCM file contract. Default tests explicitly report that the artifact comparison was not requested, while still requiring schema-1 load/save without migration and exact before/after legacy disabled-composition and schema-2 composition PCM equality. Independent analytic voice tests supply the portable numerical check. The optional baseline run and integrated build evidence are reported separately.

These checks establish storage/recall invariants and synthetic engine parity, not owner listening, real audio-device, DAW or physical power-loss qualification. Build/CTest and sanitizer evidence is recorded in the milestone report after integration.
