# UI native saved-piece playback — 7 November 2026

This milestone connects the existing Atlas/Sound Studio to the portable native playback runtime. It is an engineering integration of the existing fixed first voice, not an owner listening decision or a ceiling on the full synthesizer plan. Live sonification, new voices/mappings, modulation, regional effects, historical composition and the complete instrument targets remain separate workstreams. Existing `FRONTEND_INTEGRATION_READINESS.md` describes the earlier data-only checkpoint; this document supersedes its transport/audio availability statements only when the optional audio host advertises these methods.

## Boundary and ownership

`ui/contracts.ts` is the shared DTO source. The audio host offers `getTransport`, `setTransport`, `getAudioState` and `setAudioEnabled` in addition to the existing saved-piece read methods. A capability list enables each control independently; interface declarations do not imply implementation. `setMasterGain` remains unsupported and its slider disabled. The data-only `atlas-native ui-host` remains available with `audioAvailable:false`.

`getTransport` returns `{preparationId:string|null,generation:string,state,positionUs:string,durationUs:string}`. All decimal strings are bounded signed-int64 nonnegative values. The duration and position are native playback time, including the bounded synthesis tail; React does not extrapolate a clock, schedule notes or duplicate the audio engine. `setTransport` returns the same full authoritative state. Play/Pause/Seek require the current preparation and generation; unconditional Stop/Panic remain available safety actions. A reply must pass schema, capability and request correlation checks before presentation.

Audio state reports actual enabled/disabled/device-error status, fixed −18 dB master attenuation, sample rate when known and a visible error. Meter peak and active voice count are null when unmeasured; no signal meter or voice count is invented. The optional device name may be null. The only test simulation is the explicitly separate DEMO entry or a named silent test fixture.

C++ owns preparation, immutable audio material, callback processing, device lifecycle, timeline position and its five-second playback lease. The React shell owns one saved-material context and its presentation state above the screen router. Changing Atlas/Studio does not restart preparation or audio. Changing mode, piece, time basis or speed clears the displayed playback identity immediately, acknowledges safety panic/disable, then prepares the selected material. Preparation never automatically enables sound. The owner explicitly enables Listening and then presses Play. Live mode cannot play an old saved piece.

Current preparation/generation fences reject delayed preparation, command and poll replies from superseded material. Polls also carry a local mutation revision so an older status read cannot overwrite a later mutation. Newer native generations for the same preparation are authoritative; a changed preparation invalidates the selected playback context. Enabling the device can change native generation, so the UI reads `getTransport` immediately after enable before allowing Play. A stale cached audio-status read cannot arm a new preparation.

Pause acceptance precedes the callback fade. Return to start while sounding first pauses, polls until the native paused state is published (finite wait), then seeks with the acknowledged identity. Natural completion retains position at duration; pressing Play resets through Stop before starting again. A control failure remains visible and does not report fabricated success. Preparation errors can be retried by selecting the same piece again.

## Lifecycle and bounds

The shell polls `getTransport` every 500 ms after the previous request completes, including when the document is hidden. Each successful `getTransport` request renews the bounded audio lease. Browser/page disappearance stops and disables the native runtime on lease expiry; pagehide also sends best-effort disable/panic. Browser throttling, sleep or suspension may expire that lease. Background playback, webview lifecycle and sustained foreground/background CPU are not qualified by these checks; an expired lease requires explicit re-enable.

The development host currently supports one controlling UI window. Its lease is process-level rather than per-tab: multiple tabs can reset the shared preparation, and another tab can renew the shared lease. Multiwindow playback ownership/isolation is not implemented or qualified.

The development bridge accepts only loopback same-origin JSON POST requests, a validated V1 envelope, bounded request ID/method names, object arguments and a 16 KiB body. Native code validates method-specific values and capabilities. Its FIFO has at most 16 pending requests and one native request active; it never retries mutations. A five-second request timeout retires the child and fails all pending work. Cancelled queued work is removed. Cancelled active reads and preparation finish into a discarded response so the next selection preserves native FIFO correlation; abandoned active audible mutations retire the child. Native preparation already stops/disables old audio. Native output is capped at 8 MiB and correlation mismatches fail closed. Late output/exit from a retired child cannot affect its replacement.

Closing the server or an owned shutdown signal closes stdin and terminates its child; native EOF and the playback lease provide independent stop paths. The bridge keeps the child attached to its server and never launches a detached process. The launcher prefers the built `build/native-playback/atlas-audio-host`, allows an explicit executable environment override and otherwise retains the data-only fallback. It does not start, stop or change collection.

## Verification and limits

Meaningful frontend checks include strict TypeScript, the complete unit suite, native/demo builds and artifact separation/CSP/licence/lazy-globe checks. New unit tests reject malformed transport/audio payloads and exercise mutation-origin/envelope/body/queue rejection, cancelled preparation correlation, bounded timeout, old-child stdout and child teardown. Actual-component synthetic-host browser tests cover explicit enable, native position presentation, acknowledged controls, visible errors, unsupported master controls, screen continuity and deferred old play/preparation replies. Existing material/voice/render regressions remain separate and silent.

The actual-native browser gate uses a new disposable synthetic library and `atlas-playback-fixture-host`. It executes the real UiHost, PlaybackRuntime and DSP through a silent output test driver, covering enable/generation synchronization, polled position, pause/resume/Stop, screen continuity, Return to start during sounding, natural completion including tail and restart, rapid speed replacement, piece replacement and leaving Replay for Live. It makes no provider requests and does not read the owner library or control collectors.

Exact commands, source hashes and observed pass/fail results are recorded in `evidence/native-playback/ui-checks.json`. Physical-device output, sample-level parity, callback safety and native lease qualification belong to the named native evidence. These UI tests do not establish owner-approved sound, subjective quality, DAW support, native-webview behavior, browser background guarantees or product CPU/GPU limits.
