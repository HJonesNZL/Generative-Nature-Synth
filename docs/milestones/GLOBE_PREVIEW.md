# Bounded globe preview — 7 November 2026

Implemented in the existing H2 UI: globe defaults to all currently loaded records, with a current-window toggle; worldwide 2D fallback; searchable catalogue plus species IDs present in loaded records; all-species emphasis reset; timestamp and record/location counts; keyboard-accessible displayed-location list; selected/highlighted marker priority. The former forty-fix subset is removed. New Zealand detail clips both stations and fixes to its bounds. This is a read-only data preview; the UI host does not expose in-app playback, voice editing or rendering. The independent native offline WAV engine does not imply these UI capabilities exist.

Receiver symbols aggregate reported detections at station coordinates. They do not locate individual animals. GPS/satellite symbols retain measured fix positions, observation timestamps and uncertainty; no movement interpolation, inferred individuals or connecting tracks are added. A map selection can inspect old loaded records even when the recent incoming list is empty. No new source/provider or paid dependency was introduced.

## Exact limits and remaining backend work

- `getChanges` initially supplies the newest 200 revisions; the UI retains up to 2,000 records and then evicts older displayed entries. All loaded records means that buffer, not the whole database. The displayed observation timestamp is the newest loaded observation, not collector freshness or continuous live tracking.
- `getCatalog` samples at most 2,000 records, with at most 500 species, 500 stations and 128 sources. Species IDs found in the loaded buffer remain selectable when absent from that sampled catalogue. Catalogue refresh does not establish complete library coverage.
- Saved material remains paged through `getMaterialEvents`, but the UI only holds the first 2,000 and reports omitted records. The map shows at most 400 symbols (or the lower host limit), with shown/available symbol counts. Symbols can overlap, and the visible globe hemisphere cannot show the far side; the list and world fallback provide alternatives.
- Full-library overview needs a native bounded/paginated summary query covering the entire library: species and station totals, latest observations per species/station or tagged individual, exact selection/time bounds, continuation cursor and truncation metadata under a consistent store/revision identity. Catalogue pagination and historical event paging/search must preserve existing provenance and correction semantics. None is simulated in JavaScript here.
- Current native capabilities do not provide source health. Fresh-source reporting needs source identity plus last successful fetch, newest observation, fetch/error/disabled state, explicit coverage knowledge and the time at which health was measured. Feed polling success and latest observation age cannot replace this. Global coverage requires verified source acquisition/access/reuse work; this preview makes no all-planet or all-species-in-nature claim.

## Verification

Strict TypeScript, thirteen unit tests (six new map regressions), native/demo production builds and build separation/licence/CSP checks pass. Native fixture browser checks pass in Chrome 156 using only disposable `build/ui-browser-fixture.sqlite3`, including all-loaded scope, species search/reset, world fallback and keyboard location browsing, existing saved-material bounds/omissions, context loss/no-WebGL, screens at 1280/1440/1920 widths, and no uncaught page errors or external HTTP requests. Static bundle checks also pass, including fail-closed native injection and new overview controls. Browser output/screenshots are ignored under `ui/app/test-results/`; `native-world-overview.png` shows synthetic fixture data. Owner library and collector were not accessed or changed. Native webviews, DAWs, GPU performance, long duration behavior and actual live-source freshness are not qualified by these checks.

Integration review additionally corrected observation ordering for timezone-offset and microsecond timestamps, and retained loaded receiver positions absent from the sampled catalogue; both have unit regressions.

Independent review found that optional station metadata on a valid GPS fix could create a false receiver. Native catalogue creation and UI detection aggregation/selection now require receiver location semantics; dedicated native/UI regressions preserve the actual individual fix without fabricating a receiver.
