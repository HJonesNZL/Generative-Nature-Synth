# Completed export inventory

`atlas/exports.hpp` exposes worker-only read-only inventory. `listExports(directory, limit)` returns completed artifact IDs, scene/engine hashes, optional recorded scene name (older files use “Saved soundscape”), sample rate, frame count, duration and size. It scans at most 2,048 directory entries and returns at most 100 valid managed files ordered by modification time descending and ID ascending. Missing folders yield an empty inventory; invalid limits, symlink directories and inaccessible storage fail observably. Scan/result truncation sets `limited`.

Only lower-case 32-hex `.wav` filenames are managed. The reader verifies the writer's exact RIFF extent, extensible stereo PCM24 format/GUID/rate, fact/data frame count and bounded INFO/ICMT recipe. It seeks past PCM rather than reading large audio into memory. Current v2/v3 recipe schemas (including legacy scene revision 1) must agree with the file format and retain scene/source hashes. It validates structure and provenance metadata, not PCM authenticity or listening quality. Unknown future recipe schemas are unavailable rather than guessed.

Managed `.wav.rendering` folders are counted as unfinished; they may represent an active export or interrupted work. Malformed, truncated, unreadable or symlink managed entries increment an unavailable count and never become successful artifacts. Unrelated files are ignored. History contains no second database/index and survives process restart from final files alone.

UiHost's `listExports({limit})` adds `activeRender`, the current in-process job snapshot or null. React recovers a running job when its UI mounts, so library switching/import reloads retain progress and cancellation. Process restart does not resume partial rendering. Native save/reveal actions accept only opaque IDs; they never accept an arbitrary path from the webview. Scene export uses a separate opaque scene ID and complete native verification. Development-only same-origin routes stream managed regular files for browser tests/previews; production contains no HTTP bridge.

`export_tests.cpp` covers completed/current/legacy recipes, names, bounds, malformed headers/metadata, truncation, symlinks and staging. `ui_project_tests.cpp` covers lifecycle/recovery through the native protocol. Browser tests cover boundary validation, exact file downloads and native-worker restart. New render metadata includes the saved scene name without changing PCM or the authoritative scene hash.
