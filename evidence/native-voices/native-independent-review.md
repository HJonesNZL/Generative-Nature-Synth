Reviewed 7 November 2026 NZDT on `beta-1`, HEAD `748ec8fe6ede73317072d442f2910cfda8bff34f`, including uncommitted milestone source. Exact reviewed source hashes, compiler/OS, standalone build/run commands, full outputs and exits are retained in [thread-sanitizer.json](thread-sanitizer.json). Production source was frozen during the final sanitizer pass; this reviewer changed only evidence files in that pass.

The review covered `audio.hpp/cpp`, `playback.hpp/cpp`, `voices.hpp/cpp`, the voice paths in `ui_host.cpp`, and sidecar/lifetime setup in `audio_host_main.cpp`. It focused on voice identity, callback ownership, preparation failure, gesture recovery, bounded resources, normalized parameter conversion and durable preset failure paths. No unresolved actionable issue remained in those reviewed paths at the recorded source identity. This is a scoped source review and synthetic test result, not complete application or release qualification.

## Issues found and corrections verified in current source

| Issue and concrete trigger | Consequence before correction | Current correction and verification |
| --- | --- | --- |
| Prepared A, then attempted B; B failed before or during audio-plan construction. The host cleared/populated its slot map before preparation succeeded. | The retained A plan could lose edit routing, or B's numeric slot could edit A's species after re-enabling A. | `UiHost::Impl::load` builds `nextVoiceSlots` locally and publishes it only after successful `playback->prepare`; source verified. Existing playback tests retain the old preparation identity and disable output on failed preparation. |
| A gesture's `begin`/`change` succeeded, then its `end` encountered a callback/device failure. | The audio update rolled back but the backend gesture stayed open after the UI considered it closed, blocking Save/Revert. | The host quiesces/restores the last authoritative settings and closes a failed `end` using the prior acknowledged normalized value before reporting failure; source verified. |
| A sidecar had 513 saved species rows without a saved default. | Constructor-added default plus saved species could exceed the 513-definition live capacity. | Constructor insertion checks the complete live draft count, including default; source verified. |
| An otherwise matching seven-column sidecar included an eighth generated column. `pragma_table_info` hid it. | The unrecognized schema was accepted and Save wrote it. A disposable pre-fix fixture reproduced acceptance and a successful save. | Validation now uses `pragma_table_xinfo`, requires exactly seven columns and requires `hidden=0` for each admitted column; source verified. |
| Two hosts simultaneously initialized an empty sidecar. | Metadata could become stale between the initial read and schema creation. | Initialization now takes `BEGIN IMMEDIATE`, re-reads application/schema identity within the transaction, initializes only when still empty, and otherwise accepts only the expected identity; source verified. |
| Logarithmic inversion of a default normalized value depended on floating-point library rounding. On this platform, default decay initially returned one ULP below `.650`. | The nominal default was not a guaranteed exact physical identity; another rounding direction could change ceil-to-sample envelope boundaries. | `denormalize` explicitly returns exact minimum/maximum at 0/1 and exact physical default at its canonical normalized coordinate. Actual VoiceStore gesture/save/reopen defaults are asserted bit-exact; frame counts match at every integer rate 22,050..192,000 Hz; PCM matches legacy at five rates. |

Save uses one `BEGIN IMMEDIATE` transaction, checks the requested revision against both the draft base and current durable row, commits before marking the draft clean, and leaves drafts intact on conflict or storage failure. Revert validates the complete durable row before replacing draft state; a disappeared previously saved row is an error. These paths were source-reviewed. The real host rejects canonical-path equality and existing-file equivalence between the sidecar and wildlife library, including ordinary symlink/hardlink aliases; tests in this pass use only automatically removed disposable sidecars.

## Callback ownership and bounds audit

- There is one serial control-worker producer and one device-callback consumer. The worker performs species-ID matching, parameter/range validation, coefficient exponentials, profile storage and plan construction. An admitted action carries a numeric slot; the callback does no string lookup or SQLite/UI work.
- The one-command mailbox is fixed numeric data. The worker writes its payload before release-publishing `request`; the callback acquire-loads the request before reading it, performs at most one command per block, and release-publishes acknowledgement only after it has finished using the payload. The worker acquire-waits before reusing that slot. Only the worker waits; the callback does no waiting or retry loop.
- A timeout/device fault calls `close`: disable publication, `driver->stop()` with callback quiescence, then renderer/mailbox mutation. Plan replacement destroys the old borrower before the old plan. The callback never destroys plan ownership or the last owner of another dynamic object. This proof depends on the OutputDriver contract that `stop()` establishes quiescence.
- Snapshot payload fields shared with the callback are atomic; the callback never waits for a snapshot reader. Plan/preparation metadata is stable for the enabled callback lifetime. Worker-only mutation and quiescence remain required; this does not promise arbitrary concurrent control callers or snapshot readers during plan replacement.
- The renderer bank is a fixed 513 numeric entries, primary voices are capped at eight and retiring voices at eight. Each onset copies its coefficients, so later edits do not alter ringing/retiring voices. An edit copies one bounded entry without changing preparation, generation, device or play state. Editable plans reserve the maximum permitted note lifetime after admitted onsets, preventing a later longer decay from being cut off by the original shorter end bound.
- Per-sample work is bounded by 16 voice states and at most eight same-frame action admissions under the existing absolute-window policy; renderer blocks are bounded to 4,096 frames. The new edit consumer performs bounded scalar checks and a numeric copy. There is no visible allocation/deallocation, mutex, I/O, logging, UI call, coefficient exponential or owning-pointer retirement in that callback path. Passing allocation probes count C++ allocations/deallocations; they do not independently certify every system-library implementation.
- Per-voice gain only attenuates, preserving the inherited aggregate `.8` bound before the independent master attenuation. Existing fault handling and finite note lifetimes remain active. The implemented controls are transpose, attack, T60 decay and voice gain; unsupported synthesis controls remain outside this qualification.

## Final independent test result and limits

Apple Clang 17.0.0 on macOS 15.6.1 arm64 built both standalone suites with C++20, `-Wall -Wextra -Wpedantic -Wconversion -Werror`, `-O1 -g -fsanitize=thread -fno-omit-frame-pointer`. Both runs used `TSAN_OPTIONS=halt_on_error=1`, no suppressions, exited 0 and emitted no ThreadSanitizer diagnostic. The voice suite passed seven groups, including independent equations, actual store/default parity, 72,000 normalized boundary/random updates, species isolation, preserved ringing notes, long edited tails, capacities and acknowledged callback edits. The playback suite passed thirteen groups, including concurrent callback/plan retirement, coherent snapshots, timeout, leases, failure recovery and callback allocation probes.

ThreadSanitizer establishes no detected race in the exercised schedules; it is not a proof of all schedules, callback timing, lock freedom or absence of I/O. These executables use synthetic drivers and do not include the JUCE adapter or UI-host request paths under instrumentation. System SQLite and OS libraries were not rebuilt with instrumentation. Source review is supporting evidence for those boundaries, not a substitute for application-level failure fixtures or sustained hardware measurements. No owner database, real audio output, physical latency, DAW session or owner listening test was involved. No hardware, listening or release approval is claimed.
