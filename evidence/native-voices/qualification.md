# Native voice editing and saved definitions qualification

This milestone is an **experimental integration** on `beta-1`, not commercial release, completed whole-M2 acceptance or owner-approved sound. The first implemented struck tone exposes per-species Transpose, Attack, T60 Decay and Gain. C++ owns all synthesis, normalized-to-physical conversion, gesture validation, revisions and SQLite persistence; React presents the host's supported controls.

## Implemented behavior and evidence

The callback receives a numeric slot and precomputed coefficient set through the existing acknowledged mailbox. A bounded 513-entry bank supplies up to 512 species plus the fallback. Edits change future onsets only; already ringing notes retain their settings. The callback performs no species lookup, coefficient exponentials, preset storage or dynamic bank allocation. Eight primary plus eight retiring states and bounded note lifetimes preserve the existing headroom argument. Voice gain only attenuates: at the fixed −18 dB master, the conservative per-channel sample bound remains 0.8 × 10^(−18/20), approximately 0.100715. This is not physical loudness or a measured device waveform.

Explicit Save commits one complete definition in the independent `.state/voices.sqlite3` preset sidecar. Revisions detect competing writers. Unsaved drafts are intentionally discarded on process exit. Revert reloads the latest durable settings. Wildlife libraries remain read-only; synthetic tests compare unchanged disposable animal-library content. The sidecar is not a portable soundscape/project format, and the CLI WAV export does not yet load these presets.

Native results are retained in `final-debug.log`, `final-release.log`, `final-sanitized.log` and their command/source-hash receipts. Debug and AddressSanitizer/UndefinedBehaviorSanitizer each pass 11 CTest suites; Release passes 12 including the actual JUCE host lifecycle. The new voice suite passes seven groups: independent sample equations, actual saved/reopened default PCM at five rates, all supported integer-rate envelope boundaries, 72,000 normalized edge/random updates, per-species/captured-note isolation, extended edited tails and mailbox/state/allocation checks. Store tests exercise explicit durability, no autosave, strict schema/type validation, CAS conflicts, corruption, read-only/busy/rollback behavior and capacity. Seven full native studio protocol tests include actual rendered PCM after failed preparation and callback-stall gesture recovery.

The real `atlas-audio-host` lifecycle check prepares a disposable saved piece, edits and saves a voice, then acknowledges stop/disable and exits on stdin EOF. It never enables an output device. Its exact artifact and protocol are retained in `host-lifecycle.json`; `final-artifact.json` identifies the immutable local Release executable and source fingerprint. The initial lifecycle check failed because the prior test expected 3.0 s while editable plans deliberately reserve the last onset plus the maximum 3.12 s tail, producing 3.72 s for that fixture. `release-before-tail-expectation.*` and the corresponding lifecycle receipt retain that failure. The corrected test independently checks both the unchanged requested data window and the exact editable audio end bound; it was not relaxed to accept arbitrary durations.

Independent review and ThreadSanitizer results are in `native-independent-review.md` and `thread-sanitizer.json`. Seven voice and thirteen playback groups passed with no reported race and no suppressions. Review caught and repaired failed-preparation slot misrouting, permanently open gestures after failed end acknowledgement, implicit-fallback capacity overflow, generated-column schema acceptance, concurrent initialization and exact default conversion. The ownership audit supports the exercised tests; clean sanitizer runs do not prove every schedule or callback deadline.

Frontend evidence is recorded separately in `ui-checks.json` and `ui-independent-review.md`. It distinguishes deferred-host browser checks from actual C++ host checks using a clocked synthetic output. These tests exercise parameter acknowledgement, queue flushing, persistence/restart, selection races and native capability presentation. They do not use browser DSP or claim physical audio verification.

## Remaining qualification and product work

No new physical-output run, listening decision, sustained callback execution-time/deadline measurement, complete application CPU/GPU measurement, device hot-plug/rate-change matrix, DAW/VST3 validation, packaged-webview test, clean-machine installation or physical power-loss durability test was performed for this revision. Earlier native playback device receipts remain historical and do not qualify this changed artifact. The immutable executable is retained locally under ignored `build/`; it is not a packaged distribution.

Additional synthesis families, individual overrides, editable causal mappings/modulation, regional effects, full soundscape recall/export, live composition and selected-event audition remain on the broader instrument plan. No paid service/dependency or collection change was introduced. The next practical acceptance step is owner listening with saved material; the next engineering gates are complete authored-scene recall/export and sustained audio/UI/device qualification.
