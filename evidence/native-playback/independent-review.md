# Independent native playback review

7 November 2026. Independent agent review using Field Audio Systems ownership, callback and transport checks. Scope: `playback.hpp/.cpp`, `juce_output.cpp`, `audio_host_main.cpp`, the changed UiHost playback boundary, React preparation/status/transport path and development bridge. Existing AudioRenderer equations remain covered by the earlier M2 oracle and current PCM parity tests. No provider, owner library, recorder, collector or physical playback was used by this review workstream.

## Ownership and callback result

No confirmed actionable native ownership or mailbox defect remains in the reviewed source under its explicit one serial control-worker/one callback/driver-stop-quiescence contract. This is a source audit plus synthetic regression result, not a realtime or hardware guarantee.

- The control worker owns unique AudioPlan and AudioRenderer objects. The renderer borrows its plan. Prepare/disable/destruction first disable output and stop the driver, then panic/mutate the renderer. Replacement destroys the old borrower before its plan. JUCE's AudioIODevice::stop documentation in the existing local checkout explicitly flushes pending callbacks before returning.
- The command mailbox has one producer and one consumer and one outstanding command. Release publication transfers the plain pending DTO to the callback; release acknowledgement transfers it back. Worker acknowledgement wait is bounded at 250 ms. The callback never waits. There is no discardable note-on queue ahead of panic/stop, and zero-identity safety commands work before preparation.
- Position, generation and renderer state are atomic payloads bracketed by a sequentially consistent atomic serial. This avoids the plain-payload seqlock data race. Only the non-realtime worker retries; the callback publishes once with bounded work. Plan metadata is worker-owned and must not be read concurrently with a second control worker replacing it.
- The actual callback clears valid supplied output extents, copies preallocated interleaved scratch into planar stereo and leaves additional channels silent. Invalid renderer block sizes produce sticky failure and silence. Driver hard limits bound rejected-buffer clearing. AudioPlan compilation, memory ownership, SQLite, JSON, strings, device setup/teardown and logging remain off the callback. Source traversal found no callback mutex, wait, retry loop, filesystem or network operation.
- Device errors and a five-second lease become observable failure states. Callback frame-budget expiry silences output even if worker service stops. Worker service closes the driver. Enable is deliberate, resets to frame zero/new generation, and never starts transport by itself.

## Integrated path and corrections checked

The concrete path is saved-session verification → off-thread AudioPlan → the existing AudioRenderer → PlaybackRuntime callback → JUCE planar output. The synthetic host substitutes only the output driver; it uses the same runtime, preparation and renderer.

Material browsing now has a separate cache, so getCatalog/getMaterialEvents for another piece cannot replace the active audio preparation. Playback preparation duration includes the renderer tail. Failed preparation stops prior output and preserves the previous plan identity without exposing unverified new material. Preparation IDs and transport generations remain decimal strings across the bridge.

The development bridge serialises bounded pending requests, validates local/same-origin envelopes, correlates reply IDs, does not retry mutations, ignores retired-child output and closes the worker on active-request cancellation. React polls acknowledged native frame position, guards older replies with preparation/generation and mutation revisions, and uses no fabricated native meter or voice count. The two source-review transport findings sent to the UI implementer were: Return to start while playing reached unsupported seek, and Play after natural finish reached unsupported finished→play. The UI now waits for a published paused state before seek, with a finite wait and visible error, and sequences stop before replaying a finished piece. The UI workstream records a passing final browser execution in `ui-checks.json`.

## Later actual-host corrections and receipt review

The hardware-free runtime/fixture path did not expose two real JUCE host integration defects. The native workstream reproduced and repaired both after the initial source review:

1. The initial `ScopedJuceInitialiser_GUI` host did not create macOS NSApplication; dispatch returned before the worker's message-thread stop request, producing startup/shutdown deadlock. `audio_host_main.cpp` now enters through public `JUCEApplicationBase::main`, owns its worker from an application subclass and keeps dispatch alive until runtime/driver teardown. OS quit asks the bounded-poll worker to close before posting application quit. The real-host prepare-only test reproduces the affected lifecycle without enabling output.
2. The initial listener invalidated output on every JUCE device-list notification. CoreAudio's private aggregate-device creation generates a notification even when the chosen default remains unchanged. `juce_output.cpp` now invalidates only when the chosen output disappears or the selected default name changes. At the pinned local JUCE implementation, these type callbacks run through AsyncUpdater on the message thread, so the added names/default lookup stays off audio. Format changes, unexpected stops and errors still use their existing failure callbacks.

I inspected the final source and the native agent's before/final receipts; I did not independently run physical output. [Startup failure](device-smoke-before-fix.json) and [device-list false positive](device-smoke-device-change-before-fix.json) retain the failed artifacts. The [final device receipt](device-smoke.json), artifact SHA-256 `25ee4e92c82c428f9ccebb45e662701d2e39ad6a2e439d0f4ca5502921cd401e`, reports `passed_device_callback_smoke`: default disabled; 48 kHz/-18 dB enable without transport; advancing position beyond 0.8 seconds; settled/frozen pause; seek to 0.3 seconds; resume; stop/disable; unchanged temporary synthetic database; and clean EOF exit 0 without forced kill. [Real-host lifecycle receipt](host-lifecycle.json) separately passes with no output enable. The UI workstream's [browser/native receipt](ui-checks.json) reports its actual-runtime fake-output browser gate passing, including the corrected Return to start and finished-piece replay sequences, with no rejected replies or page errors.

These are a short actual-device callback smoke and agent-receipt review, not hardware qualification. No heard speaker audio, device-default change/unplug/recovery, sleep/wake, sustained output, callback-deadline/physical-latency measurement, whole-product CPU or owner listening conclusion is established. The earlier independent TSAN receipt remains valid for the unchanged portable runtime; it does not instrument or qualify the later JUCE application/adapter lifecycle.
