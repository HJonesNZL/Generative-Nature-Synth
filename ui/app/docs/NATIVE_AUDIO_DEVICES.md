# Native audio preferences

The header shows Audio settings only when the host advertises both `getAudioDevices` and `setAudioDevice`. The production UI continues to receive `window.atlasHost` from the native shell. Its bundled React, Three, fonts, map data and images use local relative assets. No frontend development server is needed by the package.

The mounted preferences popover owns a local device/buffer draft and the last validated catalog. Initial loading and explicit refresh disable draft controls until the catalog settles, preventing late metadata from overwriting a newly edited choice. Selecting System default, an explicit output or a buffer size sends no mutation. Apply output sends the catalog's exact `controlRevision`, `preparationId`, `generation` and complete `configuration`. Zero buffer frames requests the device default. Rates are reported as active output information rather than offered as a separate setting. Buffer choice supports stable playback; it does not introduce an input-monitoring or low-latency target.

The native control thread owns enumeration and device changes. React never opens hardware or produces audio. An accepted apply stops playback, releases notes, advances the transport generation and leaves Listening off. The header invalidates older transport polls, clears its local Listening authorization, then reads transport and audio status, including after a failed opening attempt. Recovery is explicit: refresh devices, apply an available output, enable Listening and press Play. The UI never retries mutations, starts audio or resumes playback automatically.

Catalogs are limited to 128 unique device IDs and 64 rates/buffer choices per device, with finite bounded metadata, valid decimal revision fences and an optional truthful active output. Invalid catalogs fail closed through HostClient; their contents cannot become choices. Missing, mono or unavailable device metadata is preserved. An explicit missing selection disables Apply until the user chooses an available output. The native host decides whether a particular format/output is supported. Failed queries and applies remain visible; stale fences require Refresh devices before retrying. Query requests use the existing 8-second HostClient limit; Apply allows 30 seconds for native opening, followed by a separate bounded transport read.

The shell owns read-only library selection, scene-folder/import selection, and the existing WAV anchor's native save behavior. Preferences do not expose filesystem paths, SQL or library-writing controls.
